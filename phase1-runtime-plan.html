Phase 1A proves AgentRouter can start a run, create a Daytona sandbox, launch Codex in that sandbox, stream events, upload artifacts to R2, and clean everything up. Phase 1B repeats the same contract with Claude Code as provider parity work.

starting --launch failure---------------------------> failed

running  --heartbeat stale -> recovering cleanup --> failed

Terminal states: completed, failed, cancelled.

Why it exists

  • Prevents impossible runs like completed -> running.
  • Makes cancellation safe from queued, starting, or running.
  • Lets heartbeat recovery mark stale runs without guessing.
  • Gives the cleanup sweeper one source of truth.
  • Makes run history explainable in the dashboard.
  • Lets a user reconnect and replay the run from the last event sequence.

Why Postgres stays in Phase 1

Postgres is not for agent memory. Agent CLIs run inside Daytona and write to the sandbox filesystem. Postgres is AgentRouter's control-plane ledger: run state, ordered events, artifact index, heartbeat lease, reconnect cursor, and cleanup records.

runs run_attempts run_events artifacts artifact_manifests cleanup_ledger minimal schema only

Schema rules

  • No provider API keys or OAuth tokens in Postgres. Phase 1 reads provider keys from control-plane env only and stores only the resolved credential strategy.
  • No provider-specific event tables in Phase 1. Provider fields live in redacted JSONB under a normalized event contract.
  • Postgres event rows are bounded. Large provider output stores only a redacted excerpt and R2 artifact reference in run_events.
  • No static run timeout column is required for agent lifetime. Liveness comes from worker heartbeat plus sandbox TTL renewal.
  • Terminal run states are immutable: completed, failed, and cancelled cannot transition back to running.
  • Every table that stores raw provider output stores redacted payloads only.

Provider credential boundary

Redaction is not the security boundary. The worker owns provider credentials and must prove how those credentials are kept away from model-generated shell commands before any runtime adapter can be considered shippable.

Layer Rule Release gate
Raw provider key Lives only in the control-plane worker process or secret manager. It is never stored in Postgres, R2, the sandbox image, the repo checkout, CLI argv, logs, or general sandbox env. Process, file, database, R2, and log scans use key hashes and secret canaries to prove absence.
Runtime launch Preferred path is a run-scoped provider proxy token or equivalent provider-supported credential exchange. Direct provider env such as CODEX_API_KEY or ANTHROPIC_API_KEY is allowed only if real CLI tests prove child tool commands receive a scrubbed env. If neither proxy mode nor direct-env-proven mode passes, Phase 1A is blocked.
Tool subprocesses Every model-generated shell command, repo script, dependency hook, and background process runs with a sanitized env and no readable credential file, auth config, or parent process env. Attack prompts must fail to read env, /proc/*/environ, shell history, home config, workspace files, and process argv.
Artifacts and events Redaction remains defense in depth for stdout, stderr, provider JSON, final summaries, error payloads, manifests, and workspace files. A leaked canary anywhere in Postgres, API responses, R2 objects, or local logs fails the suite.
  • credential_strategy is recorded on each attempt as provider_proxy or direct_env_proven, never as a secret value.
  • Provider credentials must never be passed through CLI argv because argv is inspectable through process listings.
  • full_access cannot ship until the credential boundary passes under full-access mode, not only under read-only mode.

Agent session archive

In Phase 1, a run is the agent session. Postgres stores the session index and ordered replay cursor; R2 stores the session archive bytes. The archive is required, not optional, and must include every artifact needed to inspect or restore the run view after the Daytona sandbox is gone. 

dev/runs/<runId>/
  session/manifest.json
  session/events-000001.ndjson.gz
  session/final-summary.json
  logs/stdout/000001.ndjson.gz
  logs/stderr/000001.ndjson.gz
  workspace/diff.patch
  workspace/file-index.json
  workspace/files/<sha256>-<safe-name>
  runtime/provider-metadata.json
  • manifest.json is the canonical session artifact: runtime kind, attempts, event range, checksums, byte sizes, file paths, redaction status, and artifact ids.
  • Workspace artifacts include agent-created files, modified files, deleted-file records, executable-bit changes, binary files, nested directories, and explicit output paths.
  • The collector does not upload .git, dependency caches, provider auth files, .env, or paths outside the checked-out workspace.
  • Long runs periodically checkpoint compressed log and event chunks to R2, then finalize the manifest on completion, failure, or cancellation.
  • If the worker crashes, recovery uploads the best available partial archive before cleanup; existing partial R2 objects stay referenced by Postgres.

Long-running output contract

Postgres is the replay index, not the log store. Provider output is normalized into small ordered events; large stdout, stderr, model traces, and event exports are compressed into R2 chunks and referenced from events and manifests.

Concern Phase 1 rule Required test
Event row cap run_events.payload_json is capped at 32 KiB after redaction. Public text excerpts are capped at 8 KiB. Larger payloads store a redacted excerpt plus artifact_ref_json. Large stdout, stderr, malformed provider lines, and final summaries never create oversized Postgres rows.
Log chunks Stdout/stderr are written as gzip-compressed NDJSON chunks under the run prefix, targeting 4 MiB compressed or 60 seconds per flush, whichever comes first. Downloaded chunks decompress, checksums match, byte ranges are present in the manifest, and redaction runs before upload.
SSE backpressure Each SSE connection has a bounded buffer: 1,000 events or 8 MiB. Slow consumers receive a final stream_backpressure event when possible, then disconnect and resume with Last-Event-ID or afterSeq. A slow client cannot block the worker, database writer, provider process, or other streams; reconnect has no gaps or duplicates.
Events API pagination GET /v1/runs/{id}/events requires cursor pagination. Default limit is 100; maximum is 500. Large event bodies are represented by artifact references, not inline bytes. Polling a long run returns bounded pages and stable cursors even while new events are being appended.
Compression R2 event exports and log chunks use application/x-ndjson with gzip encoding and store uncompressed size, compressed size, sha256, event range, and redaction status. Manifest entries round-trip exactly and can be verified without reading Postgres.
Retention Phase 1 keeps hot Postgres events for 30 days and R2 session archives for 30 days under dev/test prefixes. Cleanup is prefix-confined and never deletes another phase's objects. Retention sweep deletes only expired rows/objects for the configured prefix and leaves current manifests, active runs, and other prefixes untouched.

API design principle

The API should expose one core resource: a run. Phase 1A accepts Codex runs only, while the public shape already leaves room for Claude Code in Phase 1B. The happy path is one request to start work, one stream to watch it, one way to restore it after reconnect, and one call to cancel. Provider keys stay server-side; callers use an AgentRouter API key.

resource: run runtime.kind runtime.mode SSE stream reconnectable idempotent create session archive no provider keys in SDK

Runtime API

Endpoint Purpose
GET /v1/runs List recent and active runs for session restore.
POST /v1/runs Create a run. Accepts an Idempotency-Key header.
GET /v1/runs/{id} Return run status, timestamps, sandbox id, final summary, and lastEventSeq.
GET /v1/runs/{id}/session Return the replayable session snapshot: run, attempts, event cursor, and current R2 artifact manifest.
GET /v1/runs/{id}/stream SSE stream with bounded per-client buffer; resumes with Last-Event-ID or ?afterSeq=.
GET /v1/runs/{id}/events Paginated event history for replay and polling fallback using afterSeq; maximum page size is 500.
POST /v1/runs/{id}/cancel Move running work to cancelling and clean the sandbox.
GET /v1/runs/{id}/artifacts List R2-backed logs, manifests, patches, summaries, and workspace files.
GET /v1/runs/{id}/artifacts/{artifactId}/download Return a short-lived signed URL or stream the R2 object through the API.

Runtime selection

The API and SDK choose the agent runtime per run. Phase 1A supports codex; Phase 1B adds claude_code against the same contract. Provider credentials stay on the server; the client only selects a supported runtime kind and AgentRouter-owned mode, then receives normalized run events. 

type RuntimeKind = "codex" | "claude_code";
type RuntimeMode = "default" | "read_only" | "full_access" | "auto_review";

// Phase 1A: accepted.
await ar.runs.create({
  task: "Fix the failing checkout test",
  runtime: { kind: "codex", mode: "default" },
  source: { type: "git", repoUrl: "https://github.com/acme/app" }
});

await ar.runs.create({
  task: "Review the checkout flow",
  runtime: { kind: "codex", mode: "auto_review" },
  source: { type: "git", repoUrl: "https://github.com/acme/app" },
  review: { base: "main", includeUncommitted: true }
});

// Phase 1B: accepted after Claude Code parity lands.
await ar.runs.create({
  task: "Implement the failing test fix",
  runtime: { kind: "claude_code", mode: "full_access" },
  source: { type: "git", repoUrl: "https://github.com/acme/app" }
});

Tool model

User-defined tools are not raw functions passed into the sandbox. A tool is a registered contract: name, description, JSON input schema, output shape, execution target, credential reference, and policy. Phase 1A only allows the built-in CLI tools that Codex exposes inside the Daytona sandbox. Phase 1B applies the same rule to Claude Code.

Tool type Phase 1 behavior Future execution model
Built-in sandbox tools Supported through runtime modes: shell, file read/write, git, search, and review behavior provided by Codex in Phase 1A and Claude Code in Phase 1B. Still sandbox-local; AgentRouter records normalized command/tool events and archives resulting files.
Remote MCP tools Rejected in Phase 1. No caller-supplied --mcp-config, plugin directory, or tool server config. User registers an MCP server URL plus schemas and credential refs. AgentRouter MCP Gateway brokers calls and enforces policy.
Sandbox-local tool bundles Rejected in Phase 1 except tools already baked into the selected sandbox image. User supplies a signed image, npm/pip package, or command bundle. Worker installs or starts it as a sandbox sidecar and exposes it through MCP.
Control-plane functions Rejected in Phase 1. No arbitrary JS/Python function body is serialized into the agent run. Function lives behind AgentRouter as a webhook/serverless target. Sandbox gets only a scoped tool descriptor; execution stays behind the gateway. 
// Future SDK shape, not Phase 1
const tool = await ar.tools.register({
  name: "create_issue",
  description: "Create an issue in the tracker",
  transport: { kind: "mcp_http", url: "https://tools.acme.test/mcp" },
  inputSchema: {
    type: "object",
    properties: {
      title: { type: "string" },
      body: { type: "string" }
    },
    required: ["title"]
  },
  credentialRef: "cred_tracker_prod",
  policy: {
    allowedModes: ["default", "full_access"],
    approval: "required_for_write"
  }
});
  • Tool credentials are never copied into the model prompt or general shell environment.
  • Sandbox-local tools receive scoped env only for the tool process, not for arbitrary agent commands.
  • Remote tools execute through AgentRouter MCP Gateway so calls can be logged, redacted, approved, retried, and blocked.
  • Phase 1 API requests containing tools, mcpServers, raw --mcp-config, or raw Claude --tools/--allowedTools overrides fail before worker claim.

Session restore

Phase 1 restores the AgentRouter run session, not the internal Codex or Claude Code conversation. A reconnecting client rebuilds the view from Postgres events and R2 artifact metadata, then resumes streaming from the last event sequence it has seen. 

const restored = await ar.runs.restore({
  runId: "run_...",
  afterSeq: lastSeenEventSeq
});

const session = await ar.runs.session("run_...");
const artifacts = await ar.runs.artifacts("run_...");
console.log(session.artifactManifest.status, artifacts.items.length);

for await (const event of restored.stream()) {
  localStorage.setItem("lastEventSeq", String(event.seq));
}

Project structure

Use a small TypeScript monorepo with hard package boundaries. The API owns HTTP contracts, the worker owns execution, adapters own provider quirks, and pure domain packages own state machines and validation. Phase 1A builds the Codex adapter first; Phase 1B adds Claude Code parity without moving provider code into API handlers or the public SDK.

Review guardrails

  • package.json#exports exposes only stable entrypoints; no deep imports across packages.
  • tsconfig project references enforce build order and catch cycles.
  • dependency-cruiser or equivalent enforces forbidden imports in CI.
  • All env reads go through packages/config; tests can replace config without mutating globals.
  • Provider package code is the only place that knows Codex/Claude raw event names.
  • Every package has a README.md with responsibility, public exports, and forbidden dependencies.

Definition of done

  • Unauthorized API requests fail with the documented error schema.
  • Architecture tests enforce package dependency direction and reject deep imports.
  • Duplicate Idempotency-Key requests return the same run.
  • Duplicate Idempotency-Key with a different payload returns 409 conflict.
  • Successful run creates ordered events.
  • SSE reconnect with Last-Event-ID or afterSeq has no gaps or duplicates.
  • Slow SSE consumers disconnect without blocking worker progress and can resume from the last acknowledged sequence.
  • Cancelled run kills process and sandbox.
  • Heartbeat keeps long runs alive.
  • Stale heartbeat triggers recovery cleanup.
  • Worker crash at every external-resource boundary is recoverable.
  • Credential boundary records credential_strategy and proves raw provider keys are absent from sandbox env, argv, files, logs, events, R2, and Postgres.
  • Secret canary attack prompts cannot recover raw keys, run-scoped proxy tokens, auth files, or parent process env, including in full_access.
  • Postgres event payloads stay under the cap; large stdout, stderr, traces, and event exports are compressed into R2 chunks.
  • R2 log chunks include checksums, byte ranges, event ranges, uncompressed size, compressed size, and redaction status.
  • R2 contains only prefixed artifacts with manifest entries and checksums.
  • Every terminal run has a session/manifest.json artifact, even when the manifest is marked partial after failure.
  • Agent-created and agent-modified workspace files appear in workspace/file-index.json and can be downloaded through the API.
  • Deleted files, binary files, executable-bit changes, nested paths, and large-file cap behavior are represented in the manifest.
  • Real provider smoke test for the active milestone passes before integration and E2E tests run.
  • Forced failed runs still produce inspectable events, partial artifacts, and cleanup records.
  • Concurrent workers cannot double-run or double-clean one run.
  • OpenAPI spec validates in CI.
  • TypeScript SDK can create, list, get, restore, stream, wait, cancel, inspect sessions, list artifacts, and download artifacts.
  • Reconnected clients restore run state from lastEventSeq without duplicating events.
  • Codex adapter classifies success, failure, cancellation, malformed output, and partial summaries.
  • Phase 1B Claude Code adapter classifies success, failure, permissions, cancellation, malformed output, and partial summaries.
  • Each public mode resolves to audited Codex flags in Phase 1A and audited Claude Code flags in Phase 1B, then stores the resolved profile with the run attempt.
  • auto_review produces review findings without modifying the workspace.
  • full_access works only inside isolated Daytona sandboxes and still cannot expose provider keys.
  • User-defined tool configs are rejected in Phase 1; built-in sandbox tools still emit normalized command/tool events.
  • Unsupported runtime modes return explicit typed errors before worker launch.
  • No event stores raw API keys, proxy tokens, bearer tokens, or secret canaries.
  • Agent-launched shell commands cannot read or emit provider keys or credential-boundary tokens.
  • Retention sweeper deletes only expired objects in the configured prefix and never active runs or another phase's prefix.
  • Cleanup ledger has no unresolved resources.

OpenAPI contract

Phase 1 ships a checked-in openapi.yaml and a small TypeScript SDK. The API contract defines request/response schemas, run statuses, session snapshots, event payloads, artifact metadata, download behavior, and typed error codes for the runtime surface.

GET /v1/runs POST /v1/runs GET /v1/runs/{id} GET /v1/runs/{id}/session GET /v1/runs/{id}/stream GET /v1/runs/{id}/events POST /v1/runs/{id}/cancel GET /v1/runs/{id}/artifacts artifact download runtime.kind enum runtime.mode enum typed errors

Expected successful run

  1. Postgres creates a runs row with runtime_kind, runtime_mode, and status queued.
  2. Worker claims the run and transitions queued -> starting -> running.
  3. Postgres creates a run_attempts row and a sandbox_sessions row.
  4. Daytona sandbox is created and its lease is renewed by heartbeat.
  5. The selected adapter runs through codex exec --json or claude --bare -p --output-format stream-json.
  6. Events stream into run_events with increasing sequence numbers and bounded payloads.
  7. Run snapshot exposes lastEventSeq for reconnect and replay.
  8. R2 receives the session archive under dev/runs/<runId>/, including manifest, compressed event/log chunks, final summary, patch, and workspace file index.
  9. Run ends as completed or failed, never both.
  10. Cleanup ledger records sandbox stop/delete with no unresolved resources.

What you should see

  • GET /v1/runs/:id returns current status and timestamps.
  • GET /v1/runs/:id/session returns run state, attempts, event cursor, and the current R2 manifest.
  • GET /v1/runs/:id/events shows the full ordered timeline.
  • GET /v1/runs/:id/artifacts lists R2-backed compressed log chunks, manifest, final summary, patch, and workspace files.
  • GET /v1/runs/:id/artifacts/:artifactId/download returns the selected artifact bytes or signed URL.
  • Canceling a live run moves it to cancelling -> cancelled.
  • No raw API keys, proxy tokens, bearer tokens, or secret canaries appear in events, logs, or artifacts.
