Postgres boundary

AgentRouter stores the durable control plane in Postgres.

The database owns tenants, environments, agents, immutable agent versions, credentials metadata, MCP tool catalog, policies, approvals, runs, run timelines, usage, billing metadata, audit events, webhooks, and cleanup state. It does not store raw provider secrets or artifact bytes.

Neon Postgres UUIDv7 generated by app R2 for artifact bytes KMS for secret values Partition high-volume events
12 schema domains
43 core tables planned

Primary key stance

Use UUID primary keys for API-visible resources.

Generate UUIDv7 in the application so IDs are sortable enough for indexes and safe to expose through REST, SDKs, logs, and webhooks.

Versioning stance

Agents are mutable; agent versions are immutable.

Every run references the exact deployed agent version, policy set, model, tool bindings, sandbox template, and source binding used at start time.

Security stance

Store references, hashes, and audit trails.

Postgres keeps key prefixes, secret fingerprints, KMS references, scopes, rotations, approvals, and access logs. Secret material stays out of rows.

Runtime Write Path

The worker owns execution, but Postgres owns the durable state machine.

POST /runsCreate `runs` row with status `queued`, runtime_kind, runtime_mode, input_json, agent_version_id, idempotency_key_hash, idempotency_request_hash, and last_event_seq.
worker claimUse `for update skip locked` to atomically claim queued runs, create `run_attempts`, and attach worker_id.
sandbox startCreate `sandbox_sessions`; append bounded `run_events` entries for created, started, heartbeat, stdout refs, stderr refs, and status.
runtime adapter`run_attempts.runtime_kind` selects Codex or Claude Code; `credential_strategy` records provider_proxy or direct_env_proven without storing secrets; `run_events` stores the normalized raw stream; `artifacts` stores R2 object metadata.
approval gate laterFuture phases create `approval_requests` as separate queue rows. Phase 1 run status stays within queued, starting, running, cancelling, cancelled, completed, and failed.
archiveCheckpoint gzip-compressed log chunks, event export chunks, workspace file index, and partial manifests to R2 during long runs.
finishComplete `runs`, finalize usage events, upload final session manifest, and enqueue cleanup ledger rows.

Do not overload one status. `runs.status` is product state. `run_attempts.status`, `sandbox_sessions.status`, and `cleanup_ledger.cleanup_status` track lower-level resources. Approval, timeout, and cleanup details live in those lower-level tables until later phases add product-level states for them.

Index Rules

These should be enforced in code review and migration review.

Foreign keys

Every FK gets an index.

Postgres does not create FK indexes automatically. Missing indexes hurt joins and make cascades or deletes scan child tables.

Queue claims

Partial indexes for hot statuses.

Queued runs, pending approvals, active keys, and cleanup retries all need small partial indexes matching their worker queries.

JSONB

Index only queried payload paths.

Use JSONB for flexible configs and redacted payloads, but add GIN or expression indexes only after a real query needs them.

Common composite indexes
runs (org_id, environment_id, status, queued_at desc)
runs (org_id, environment_id, runtime_kind, runtime_mode, status, queued_at desc)
runs (agent_id, status, queued_at desc) where agent_id is not null
run_events (org_id, environment_id, created_at desc)
run_events primary key (run_id, sequence)
approval_requests (org_id, environment_id, risk_level desc, requested_at asc)
audit_events (org_id, environment_id, created_at desc)
usage_meter_events (org_id, created_at desc, metric)
Worker claim query
update runs
set status = 'starting',
    claimed_at = now()
where id = (
  select id
  from runs
  where status = 'queued'
  order by priority asc, queued_at asc
  limit 1
  for update skip locked
)
returning *;

Retention And Boundaries

Keep Postgres small enough to stay operationally boring.

Partition

run_events, audit_events, usage_meter_events

Keep run_events unpartitioned in Phase 1 because rows are bounded and large bytes are in R2. Create monthly partitions once volume is real. Keep recent partitions hot, archive or drop old partitions by customer plan.

Archive to R2

Move session bytes out.

Session manifests, gzip event exports, gzip logs, model trace chunks, stdout/stderr chunks, patches, screenshots, and workspace file artifacts are R2 objects referenced by `artifacts` rows with checksums and byte ranges.

Protect secrets

No raw values in rows or events.

Use redacted JSONB payloads. Store `secret_ref`, `secret_hash`, `fingerprint`, `prefix`, and non-secret `credential_strategy`, never provider API keys, proxy tokens, or webhook secrets.

Migration order: start with tenancy, environments, projects, agents, agent_versions, provider_credentials, runs, run_attempts, run_events, artifacts, and cleanup_ledger. Add MCP, policy, approvals, billing, webhooks, and rollups as those product surfaces land.
